## What changed

**The first release: analytics as a plugin — dashboards, four tenant-scoped cubes, one fact table,
three UI routes and three CLI commands, all of it the Launch kit's §8 up to 0.5.0.**

From kit 0.6.0 the kit is bare and this repository is where dashboards live. What a kit that
installs it gains:

- **Dashboards** — `analytics_pages` (jsonb `DashboardConfig`, unique slug per tenant,
  restrictable to groups), `/api/analytics/pages|templates|facts`, and the list, view and explore
  pages.
- **One template** — `tenant-overview` ("Organisation Overview"), copied into every organisation
  by `onTenantCreated` and lazily repaired on every `GET /pages`.
- **The semantic layer** — four cubes (`ActivityEvents`, `TenantActivityDaily`, `TenantUsers`,
  `Users`) served by drizzle-cube at `/cubejs-api` and `/mcp`, each scoping its own `sql()` by
  tenant.
- **One fact table** — `analytics_tenant_activity_daily_facts`, rebuilt per tenant by the
  `15 * * * *` cron, with `launch analytics check-facts` and `refresh-facts` over it.
- **Two CASL subjects** — `Dashboard` (admin+ manage, member read) and `Analytics` (read for every
  role; the cube API is read-only by nature).
- **A contribution seam** — another plugin adds cubes, fact tables, dashboard templates and
  cube-isolation cases through `analyticsExtensions({...})` from `@/plugins/analytics`, declaring
  `requires: { plugins: ['analytics'] }`.

## How to apply

This is the first release; there is nothing to port.

1. Read the install plan, then apply it — which also installs the declared dependencies
   (`drizzle-cube` pinned exactly, `recharts`, `d3`, `react-grid-layout`, `react-is`) into
   `apps/web`:
   ```bash
   pnpm plugin add https://github.com/rocketflare-dev/rocketflare-plugin-analytics.git@1.0.0
   pnpm plugin add https://github.com/rocketflare-dev/rocketflare-plugin-analytics.git@1.0.0 --apply
   ```
2. Generate and run the host's own migration:
   `pnpm db:generate --name plugin-analytics-1.0.0 && pnpm db:migrate`.
3. Add `"15 * * * *"` to `[triggers].crons` and `"/cubejs-api"`, `"/cubejs-api/*"`, `"/mcp"`,
   `"/mcp/*"` to `[assets].run_worker_first` in BOTH wrangler tomls — `pnpm provision cloudflare
   <env>` writes them, and the parity test reads `API_PREFIXES`, so a forgotten entry fails the
   gate rather than silently serving the app shell to an `<object>` embed.
4. In `apps/web/vite.config.ts`, add `'/cubejs-api': proxyTo()` and `'/mcp': proxyTo()` to the dev
   proxy, alias `'@nivo/heatmap'` to `./src/plugins/analytics/ui/lib/nivo-heatmap.tsx`
   (drizzle-cube's heat-map chunk names that optional peer and Rollup fails the build without it),
   and add `'recharts'` to `resolve.dedupe`.
5. Confirm the chart libraries stayed in the analytics chunk:
   `grep -c recharts apps/web/dist/ui/assets/index-*.js` must be 0.

## Conflicts to expect

None on a clean kit at 0.6.0. On an app that has drifted:

- The five barrel lines `pnpm plugin add` writes → they reject only if you have edited them by
  hand → take the new line; the rename translator has already rewritten this plugin into your
  vocabulary.
- `analytics_tenant_activity_daily_facts`, on an app that carried the kit's analytics before
  0.6.0 → the fact table is renamed under the `<id>_*` rule, so `pnpm db:generate` emits a `DROP`
  and a `CREATE` → install this plugin BEFORE running `pnpm db:generate`, answer **create table**
  to drizzle-kit's rename prompt, and let the `:15` cron refill it within the hour (or run
  `launch analytics refresh-facts` now). `analytics_pages` and `analytics_page_groups` are
  unchanged, so their rows survive untouched.

## Verify

1. `pnpm lint && pnpm typecheck && pnpm test && pnpm build` is green, including this plugin's own
   tests under `apps/web/src/plugins/analytics/tests/` — in particular `cube-isolation.test.ts`,
   which queries every cube as two tenants and proves each sees only its own rows.
2. `pnpm plugin check` exits 0 and lists `analytics`.
3. Signed in, **Analytics** appears in the nav and on Home, and the seeded **Organisation
   Overview** page renders with live member and activity numbers.
4. `launch analytics pages list --json` prints the page, and
   `launch analytics check-facts` reports the fact table `fresh` and exits 0.
5. An unauthenticated `curl -i <host>/cubejs-api/v1/meta` is a JSON 401, never HTML.
