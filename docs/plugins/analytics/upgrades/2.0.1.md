## What changed

**2.0.0 could not be installed with a green gate**: its anchor still said `1.0.2`, so every install
reported a version mismatch against the recorded surface and exited 1, taking the whole host gate
down with it.

- The anchor is `apps/web/src/plugins/analytics/plugin.json` — the file copied into a host, and
  the one `pnpm plugin check` compares against the recorded surface; the message was
  `plugin.json says 1.0.2, and the surface says 2.0.0`, and that is a FAILURE rather than a
  warning.
- Nothing about what analytics does changed: this is the version stamp and nothing else.
- The cause was invisible for three releases: a plugin carries its version TWICE, in
  `rocketflare-plugin.json` — the release manifest read from this repository — and in the
  anchor, which is what actually reaches a host, and `release.mjs` only ever stamped the manifest.
- While each plugin was its own repository the anchor was kept in step BY HAND and nothing said
  so; moving analytics into a monorepo dropped that habit, and the next release surfaced it.
- Kit 0.7.0's `release.mjs` stamps every manifest's declared anchor, so this cannot recur — and
  this release was cut with that fix rather than hand-patched, which is what proves it.

## How to apply

`pnpm plugin upgrade analytics` if you are on 2.0.0. Nothing else: no migration, no schema change,
no code change.

If you installed 2.0.0 you will have seen `pnpm plugin check` fail on the version mismatch. There is
nothing to undo — the anchor is data, and 2.0.1 corrects it.

## Conflicts to expect

None. One version string in one file.

## Verify

```bash
pnpm plugin check   # exits 0, with no version mismatch for analytics
```
