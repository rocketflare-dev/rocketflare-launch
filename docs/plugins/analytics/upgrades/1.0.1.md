## What changed

**Installing this plugin no longer leaves the host unable to build**: it declares the two
`apps/web/vite.config.ts` lines it needs as `coreEdits[]`, which kit 0.6.1 applies on install and
reverts on removal.

- The defect: drizzle-cube's heat-map chunk imports `ResponsiveHeatMap` from `@nivo/heatmap`, an
  OPTIONAL peer that is not installed, and Rollup fails the entire UI build rather than treating
  it as optional.
- Why printing the step was not enough: the alias lives in `apps/web/vite.config.ts`, a CORE file
  a plugin may not edit, so 1.0.0 printed it as a "by hand" step — which works for a person
  following an install plan and fails for anything unattended, such as a CI job that installs this
  plugin and runs the gate.
- The mechanism: kit 0.6.1's `coreEdits[]` has a plugin DECLARE the lines a core file needs and
  the HOST write them, exactly as `bindings[]` declares a resource `provision cloudflare` writes;
  the rule is unchanged, and this plugin still edits nothing.
- Declared: the dev-proxy prefixes `'/cubejs-api'` and `'/mcp'`, after the `'/ws'` line.
- Declared: the `'@nivo/heatmap'` alias pointing at this plugin's stub at
  `apps/web/src/plugins/analytics/ui/lib/nivo-heatmap.tsx`, after the `'@'` alias.
- NOT declared: the `recharts` entry in `resolve.dedupe` — `coreEdits` inserts a line after an
  anchor and does not modify an existing one, and a measured build without it is clean, so add it
  by hand only if you see React duplicated across chunks.

## How to apply

1. Confirm the host is on kit 0.6.1 or later (`pnpm plugin check`); an older kit ignores
   `coreEdits`, so the `@nivo/heatmap` alias stays a hand edit there and nothing breaks.
2. Run `pnpm plugin upgrade analytics`. If you already applied the `apps/web/vite.config.ts` lines
   by hand as 1.0.0 told you to, there is nothing further to do: `applyCoreEdits` is idempotent
   and leaves a line that is already present alone.

## Conflicts to expect

None. The only changed files are the two manifests, and the change is additive.

## Verify

1. On a clean kit 0.6.1, `pnpm plugin add <this repo>@1.0.1 --apply` prints
   `✔ core edit(s) applied to apps/web/vite.config.ts`, and `pnpm build` is green with no hand
   edits.
2. `pnpm plugin remove analytics --apply` returns `apps/web/vite.config.ts` to its original bytes.
3. `grep -c recharts apps/web/dist/ui/assets/index-*.js` is still 0.
