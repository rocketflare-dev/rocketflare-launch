## What changed

**The floor moves to kit 0.6.1, because 0.6.0 could never host this plugin with a green gate.**

- Installed into kit 0.6.0, this plugin's declared cron and route prefixes trip a parity rule that
  release demands be satisfied before `pnpm provision cloudflare <env>` has had a chance to write
  them — a state nothing can satisfy.
- Kit 0.6.1 narrowed that rule to `REQUIRE_PROVISIONED=1`, where it still stops a deploy but no
  longer fails an ordinary `pnpm test`.
- 0.6.1 is also the release that reads the `coreEdits[]` this plugin declared in 1.0.1; on 0.6.0
  those are ignored and the `@nivo/heatmap` alias stays a hand edit.
- Only the declared range changed: it said `>=0.6.0` because that was true when analytics stopped
  being core, it has not been true in practice since, and a range is a claim about what works.

## How to apply

1. Upgrade the kit to 0.6.1 or later: `pnpm kit:upgrade`.
2. Run `pnpm plugin upgrade analytics`. On a kit already at 0.6.1 or later there is nothing to
   do — no code changed, only the declared range.
3. To stay on kit 0.6.0, stay on analytics 1.0.1 instead: it works there exactly as well as it did
   before, which is to say with the parity test failing until you provision.

## Conflicts to expect

None. The only changed files are the two manifests.

## Verify

1. `pnpm plugin check` exits 0 on a kit at 0.6.1 or later.
2. This plugin's CI resolves ONE kit leg rather than two:
   `requires.kit '>=0.6.1 <1.0.0' → 0.6.1`.
